AURA — Native Audio Build (v2)
================================

چیزی که این پکیج هست
---------------------
نسخه‌ی Electron از AURA که به‌جای فقط Web Audio API مرورگر، از یه موتور
صوتی native (WASAPI از طریق naudiodon/PortAudio) برای پخش استفاده می‌کنه.
Decode با ffmpeg (باندل‌شده) انجام میشه.

نسبت به v1 چی عوض شده
-----------------------
✅ بیت‌پرفکت واقعی: v1 همه‌چیز رو بی‌قید‌وشرط روی ۴۴۱۰۰Hz/16-bit دیکود
   می‌کرد، حتی اگه فایل ۴۸kHz/24-bit بود. الان قبلش با یه پاس سریع
   ffmpeg نرخ نمونه‌برداری و بیت‌عمق واقعی فایل تشخیص داده میشه و دیکود
   دقیقاً روی همون فرمت انجام میشه. اگه دستگاه خروجی اون فرمت رو
   پشتیبانی نکنه، خودکار به ۴۴۱۰۰/16-bit برمی‌گرده و صادقانه یه toast
   نشون میده (usedFallbackRate) — نه اینکه سکوت کنه.
✅ EQ گرافیکی (۱۲/۳۲/۶۴ باند) + Tone Control (Preamp/Balance/Bass/
   Treble/Vocal/Presence/Air) الان روی مسیر native هم واقعاً اعمال
   میشه — قبلاً فقط روی Web Audio بود. دیزاین بایکوادها دقیقاً همون
   فرمول RBJ Cookbook‌ای هست که خود Web Audio API استفاده می‌کنه، برای
   اینکه صدا بین دو مسیر فرق نکنه.
✅ Crossfade واقعی روی native (دو «دک» هم‌زمان میکس میشن) — دیگه لازم
   نیست موقع کراس‌فید بره رو Web Audio، به شرطی که ترک قبلی خودش از
   قبل روی native داشته پخش می‌شده.
✅ نوار پیشرفت / زمان / سینک لیریک / A-B ریپیت الان تو حالت native هم
   واقعی و زنده‌ان (قبلاً چون به المان <audio> وصل بودن، فریز می‌شدن —
   حتی seek هم عملاً هیچ‌کاری نمی‌کرد چون duration رو صفر می‌خوند).
✅ سوییچ Native روشن/خاموش وسط آهنگ الان بی‌درز کار می‌کنه — از همون
   لحظه‌ای که هستی ادامه می‌ده، نه از اول.
✅ باگ واقعی پیدا شد و فیکس شد: تشخیص خودکار سکوت (auto-skip-silence)
   و ویژوالایزر اسپکتروم از یه آنالایزر Web Audio می‌خوندن که موقع پخش
   native همیشه ساکته — یعنی auto-skip می‌تونست غلط وسط آهنگ بپره.
   الان موقع native غیرفعال/فریز میشن به‌جای غلط رفتار کردن.
✅ پیش‌نمایش AURA REMIX دیگه هم‌زمان با ترک اصلی پخش نمی‌شه (قبلاً هر
   دو می‌تونستن روی هم پخش بشن چون remix از یه <audio> کاملاً جدا
   استفاده می‌کنه)
✅ باگ activate در main.js (macOS) فیکس شد — قبلاً app.emit('ready')
   رو دوباره صدا می‌زد که کار نمی‌کرد؛ الان createWindow() مستقیم صدا
   زده میشه.
✅ لتنسی: چانک‌های پخش از ~۱۰۰ms به ۴۰ms کم شدن و نوشتن به دستگاه الان
   واقعاً به backpressure استریم (drain event) گوش میده، نه فقط یه
   تایمر کور — ریسک قطعی/glitch کمتر شده.

نسبت به v2 چی عوض شده (این پاس — باگ‌گیری)
----------------------------------------------
✅ خرابی صدا (نویز) وقتی دستگاه 24-بیت رو ساپورت نمی‌کرد فیکس شد — قبلاً
   بی‌سروصدا می‌رفت رو 16-بیت درحالی‌که PCM هنوز 24-بیتی بود (بایت‌ها
   اشتباه خونده می‌شدن)؛ الان خطا میده و درست دوباره decode می‌کنه.
✅ قطعی کوتاه صدا رو پیک‌های حداکثری (که با EQ بوست‌شده خیلی معموله)
   فیکس شد — یه رنج مجاز اشتباه باعث می‌شد اون چانک کلاً drop بشه.
✅ ریس‌کاندیشن تو کراس‌فید native فیکس شد — اگه decode یه ترک بیشتر از
   ۲۰۰ میلی‌ثانیه طول می‌کشید، ممکن بود دوبار هم‌زمان کراس‌فید شروع بشه.
✅ سوییچ کردن به Native وسط پخش دیگه یه لحظه صدای دوبل نداره — قبلاً
   المان Web Audio تا لحظه‌ی موفقیت native همچنان پخش می‌کرد (هم‌پوشانی
   کوتاه صدا)؛ الان قبل از تلاش برای هندشیک، پاز می‌شه.
✅ سوییچ کردن از Native به Web Audio دیگه سرعت/پیچ (Speed/Pitch) رو گم
   نمی‌کنه — قبلاً موقع این هندآف به مقدار پیش‌فرض برمی‌گشت.

چیزی که هنوز داخلش نیست (صادقانه بگم)
----------------------------------------
❌ PureCore (کلیک/پاپ‌کیلر)، دیستورشن، دیلی/اکو، ریوربِ کانولوشن،
   واید‌کننده‌ی Mid-Side، پن‌خودکار 8D، کمپرسور داینامیک — این‌ها فقط
   رو Web Audio هستن. پورت‌کردن یه ریوربِ کانولوشن واقعی و کمپرسور
   real-time به PCM خام تو Node، کار بسیار بزرگ‌تری از این پاسه.
❌ لیمیتر واقعی (lookahead) روی native — به‌جاش یه hard-clamp ساده‌ست؛
   جلوی کلیپ دیجیتال رو می‌گیره ولی به آرومی/موزیکالی یه لیمیتر واقعی
   نیست.
❌ اگه ترک بعدی که قراره کراس‌فید بشه، فرمتش (نرخ/بیت‌عمق) با استریم
   بازِ فعلی فرق داشته باشه، برای میکس‌شدن resample میشه روی فرمت
   فعلی — یعنی بیت‌پرفکت کامل فقط وقتی صدق می‌کنه که کراس‌فید در کار
   نباشه؛ همون trade-off ای که هر پلیر واقعی با کراس‌فید داره.
❌ ASIO واقعی (لایسنس Steinberg مانعشه) — همون WASAPI که همچنان از
   Web Audio بهتره.

مهم — این کد اجرا/تست نشده
-----------------------------
این پاس تو یه محیط sandbox بدون Electron/دستگاه صدا/npm install نوشته
شده — یعنی سینتکس main.js/preload.js چک شده (node --check) و ریاضیات
EQ/کراس‌فید با تست‌های جدا (بدون naudiodon واقعی) شبیه‌سازی و درست
تایید شده، ولی خودِ اجرای واقعی روی WASAPI رو من ندیدم. لطفاً بعد از
build، حداقل این‌ها رو چک کن: صدای EQ واقعاً عوض میشه؟ کراس‌فید بین دو
آهنگ گلیچ/پاپ نداره؟ سوییچ Native وسط آهنگ درز نداره؟ هر چی عجیب بود
بگو دقیقاً فیکسش کنم.

ساخت / اجرا
-------------
۱. BUILD.bat رو اجرا کن
۲. اگه Node نصب نباشه، با winget خودش نصب می‌کنه (یه بار دیگه اجرا کن)
۳. ازت می‌پرسه مستقیم اجرا کنی (npm start) یا EXE بسازی
۴. برای تست سریع «y» بزن

اگه npm install رو خطای کامپایل داد
--------------------------------------
naudiodon یه native module هست، پس نیاز داره:
- Python 3 نصب باشه
- Visual Studio Build Tools با کامپوننت "Desktop development with C++"
